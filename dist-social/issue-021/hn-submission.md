## First comment by the submitter

> The post reads six November 2026 sources, each with its own population and definitions:
>
> - LeadDev AI Code Review Report (https://leaddev.com/the-ai-code-review-report-2026): 377 engineers and leaders. 45% name review capacity as the biggest drag on delivery; 26% fully understand the AI code they review.
> - SlashData (https://www.slashdata.co/research/faster-code-heavier-checks): 11,099 developers. 81% say AI raises the need for review and verification; 48% always check AI code before committing.
> - Sourcegraph Big Code report (https://sourcegraph.com/blog/big-code-report-2026): 1,028 respondents. 54% estimate more than 60% of AI-generated work needs substantial rework before release.
> - Atlassian AI SDLC Index (https://www.atlassian.com/blog/company-news/introducing-the-atlassian-ai-sdlc-index): AI code share 49% to 69.7% from April to October 2026; survival of AI code in later commits 79.9%, 58.9%, 68.2%.
> - DX (https://newsletter.getdx.com/p/the-10x-org-is-in-your-grasp): PR size +122% over four quarters; 80%+ AI-code orgs wait 2x for first review.
> - IT Pro on Adaptavist's survey (https://www.itpro.com/software/development/organizations-need-to-help-developers-grow-alongside-the-technology-dejected-devs-lament-career-prospects-amid-ai-advances): 63% say AI reduced how much they learn by coding.
>
> Caveats: four are surveys of perception, the survival rate is not a defect rate, Atlassian's October rebound is one month of data, and the Adaptavist figures come through secondary reporting. None measures reviewer hours directly. If you track time to first review on AI-written PRs, what does your data show?
